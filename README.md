Why I Am Still Here

## Coding as Part of My Practice

To be honest, I am not a “pure” designer or artist. During my studies and work, I have already encountered a great deal of coding, and I found it genuinely interesting. It has gradually become part of my life and one of the main ways in which I collaborate with computers. Therefore, I want to answer the question “Why are we here?” from the perspective of a game developer and technical artist.

AI can now produce working code from a short prompt, and its ability will continue to improve. However, this does not make learning programming meaningless. For me, the purpose of learning code is no longer simply to type every line manually. It is to understand the systems I build, judge the work produced by AI, and turn creative or production problems into precise and reliable tools.

## AI Can Accelerate Work, but It Cannot Own the Risk

In real production, AI cannot be trusted without verification. This does not mean that AI is always unreliable. It means that the acceptable level of trust depends on the consequences of an error. In a small experiment, incorrect code may only waste a few minutes. In a large game codebase, however, one careless modification could break dependencies, damage an asset pipeline, or introduce a problem that appears much later.

Commercial projects contain years of accumulated code, tools, assets, conventions, and undocumented decisions. An AI assistant does not automatically understand all of this context. Sometimes the safest choice is not to let it edit a valuable project directly. When something fails, a developer still needs to trace the problem, read the relevant code, evaluate the proposed change, and decide whether it is safe. Without programming knowledge, I could ask AI to generate an answer, but I could not take informed responsibility for that answer.

This changes the role of coding rather than removing it. Writing every line becomes less important, while reading, specifying, testing, and judging become more important. AI can be a fast collaborator, but it should not become an invisible authority.

## Programming Lets Me Build My Own Solutions

My internship at Tencent gave me a concrete example. Internal documentation and workflows became outdated as the project evolved. Files were numerous and scattered across different locations, so finding an accurate answer could be slow. Instead of accepting this as an unavoidable inconvenience, I coded a retrieval-augmented generation system to organize and search the project material. I then connected it to an AI assistant so that users could ask questions and receive relevant answers with traceable sources.

The important part was not merely “using AI.” Programming allowed me to define how documents were processed, how information was retrieved, and how the answer could be checked against its source. My knowledge of code turned a general-purpose model into a tool designed for a specific production environment.

The same principle applies to repetitive technical-art tasks. Imagine checking hundreds or thousands of game materials for incorrect settings. Manual inspection consumes time, attention, and money, while human reviewers may still miss inconsistent assets. A relatively small script can scan them, identify likely problems, and produce a report for an artist to review. AI may help me write that script faster, but programming knowledge allows me to define the rules, validate the results, and adapt the tool when the production pipeline changes.

## Code Is Also a Way of Understanding

During my internship, I also used AI-assisted programming to build a handwritten-image recognition experiment. The goal was not only to obtain a working model. By implementing the process, debugging it, and observing its failures, I gained a more concrete understanding of how AI systems operate. I was using code to understand AI and AI to understand code.

This experience connects with Dylan Beattie’s *The Art of Code*. Beattie presents code not only as infrastructure for useful software, but also as a creative medium through examples such as generative art, unusual programming languages, and live coding performances. His argument matters to me because a technical artist also works between expression and engineering. Code does not merely execute an idea after the creative work is finished; its structures, constraints, and possibilities influence what I am able to imagine in the first place.

If I relied entirely on generated code, I might still produce results, but my relationship with the medium would become shallow. A painter does not need to manufacture paint, but understanding how paint behaves expands what the painter can intentionally create. In the same way, I do not need to write every function without assistance, but I need enough knowledge of code to explore, direct, question, and refine computational work.

## Why I Am Here

I am not learning programming because I believe humans will always write code faster than machines. I am learning it because speed is only one part of making something valuable. A game developer or technical artist must understand context, recognize risk, design workflows, and make creative decisions. AI strengthens these abilities when it is used by someone who can evaluate it.

Programming gives me agency. It lets me move from noticing a problem to building a solution, from receiving an AI-generated result to understanding whether it deserves my trust, and from consuming technology to shaping it. That is why, even in 2026, I am still here.
